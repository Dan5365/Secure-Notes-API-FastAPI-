# Secure Notes API - Микросервисная Архитектура

[![EN](https://img.shields.io/badge/lang-EN-blue)](README_EN.md)

Безопасная, масштабируемая система управления заметками, построенная на FastAPI с использованием микросервисной архитектуры. Этот проект демонстрирует современные практики разработки программного обеспечения, включая разделение сервисов, аутентификацию, авторизацию и валидацию данных.

## 🏗️ Обзор Архитектуры

Этот проект следует паттерну **микросервисной архитектуры**, состоящей из двух независимых сервисов:

### Сервисы

1. **Auth Service** (`auth-service/`)
   - Порт: `8001` (маппинг с порта контейнера `8000`)
   - Обрабатывает аутентификацию пользователей, авторизацию и управление пользователями
   - Управляет генерацией и валидацией JWT токенов
   - Реализует ролевой контроль доступа (RBAC)

2. **Notes Service** (`notes-service/`)
   - Порт: `8002` (маппинг с порта контейнера `8000`)
   - Обрабатывает CRUD операции с заметками
   - Зависит от Auth Service для проверки токенов
   - Управляет заметками пользователей с проверкой владения

### Межсервисное Взаимодействие

Notes Service взаимодействует с Auth Service через HTTP запросы для проверки JWT токенов. Это демонстрирует паттерн **аутентификации между сервисами**, где:
- Notes Service выступает клиентом для Auth Service
- Auth Service предоставляет endpoint `/verify-token`
- Сервисы взаимодействуют через внутреннюю сеть Docker (`auth-service:8000`)

## 🔐 Аутентификация и Авторизация

### Процесс Аутентификации

1. **Регистрация Пользователя**: Пользователи регистрируются с именем пользователя, паролем и возрастом
2. **Вход Пользователя**: Пользователи проходят аутентификацию и получают JWT токен доступа
3. **Доступ на основе Токена**: Все защищенные endpoints требуют Bearer токен в заголовке Authorization

### Ролевой Контроль Доступа (RBAC)

Система реализует три роли пользователей:

- **`user`** (по умолчанию): Обычные пользователи, которые могут управлять своими заметками
- **`admin`**: Могут просматривать всех пользователей и информацию о пользователях
- **`creator`**: Наивысший уровень привилегий, могут повышать пользователей до роли администратора

### Функции Безопасности

- **Хеширование Паролей**: Использует `bcrypt` через `passlib` для безопасного хранения паролей
- **JWT Токены**: JSON Web Tokens (алгоритм HS256) для аутентификации без состояния
- **Проверка Токенов**: Централизованная валидация токенов через Auth Service
- **OAuth2 Password Flow**: Реализует OAuth2PasswordBearer для извлечения токенов

## ✅ Валидация Данных

Проект использует **Pydantic** для комплексной валидации данных на уровне API:

### Валидация Пользователя

- **Имя пользователя**: 
  - Минимальная длина: 3 символа
  - Максимальная длина: 30 символов
- **Возраст**: 
  - Диапазон: от 0 до 120 (включительно)
  - Должно быть валидным целым числом
- **Пароль**: 
  - Обязательное поле
  - Хешируется перед сохранением (никогда не хранится в открытом виде)

### Валидация Заметок

- **Заголовок**: 
  - Минимальная длина: 1 символ
  - Максимальная длина: 100 символов
  - Обязательное поле
- **Содержание**: 
  - Минимальная длина: 1 символ
  - Обязательное поле
- **Временные метки**: 
  - Автоматически генерируются с часовым поясом UTC
  - `created_at`: Устанавливается при создании заметки
  - `updated_at`: Обновляется при изменении заметки

### Преимущества Валидации

- **Типобезопасность**: Автоматическая проверка типов и преобразование
- **Санитизация Ввода**: Предотвращает попадание невалидных данных в систему
- **Документация API**: FastAPI автоматически генерирует OpenAPI документацию из моделей Pydantic
- **Сообщения об Ошибках**: Понятные, описательные ответы об ошибках валидации

## 📋 Функции

### Функции Auth Service

#### Управление Пользователями
- **POST `/users/register`**: Регистрация нового пользователя
  - Проверяет уникальность имени пользователя
  - Хеширует пароль перед сохранением
  - Возвращает информацию о пользователе (исключая пароль)
  
- **POST `/users/login`**: Аутентификация и получение JWT токена
  - Проверяет учетные данные
  - Возвращает токен доступа и тип токена
  
- **GET `/users/users`**: Список всех пользователей (только для Admin/Creator)
  - Требует роль admin или creator
  - Возвращает список всех зарегистрированных пользователей
  
- **GET `/users/users/by-username/{username}`**: Получить пользователя по имени пользователя (только для Admin/Creator)
  - Требует роль admin или creator
  - Возвращает информацию о конкретном пользователе

#### Управление Ролями
- **POST `/users/users/{user_id}/make-admin`**: Повысить пользователя до администратора (только для Creator)
  - Требует роль creator
  - Обновляет роль пользователя на "admin"

#### Проверка Токена
- **GET `/auth/verify-token`**: Проверить валидность JWT токена
  - Используется Notes Service для межсервисной аутентификации
  - Возвращает информацию о пользователе, если токен валиден

### Функции Notes Service

#### CRUD Операции с Заметками
- **GET `/users/notes`**: Получить все заметки аутентифицированного пользователя
  - Требует валидный JWT токен
  - Возвращает только заметки, принадлежащие пользователю
  
- **GET `/users/notes/{note_id}`**: Получить конкретную заметку по ID
  - Требует валидный JWT токен
  - Проверяет владение заметкой
  - Возвращает 404, если заметка не существует или не принадлежит пользователю
  
- **POST `/users/notes`**: Создать новую заметку
  - Требует валидный JWT токен
  - Автоматически связывает заметку с аутентифицированным пользователем
  - Валидирует заголовок и содержание
  
- **PUT `/users/notes/{note_id}`**: Обновить существующую заметку
  - Требует валидный JWT токен
  - Проверяет владение заметкой
  - Обновляет временную метку `updated_at`
  - Возвращает 404, если заметка не существует или не принадлежит пользователю
  
- **DELETE `/users/notes/{note_id}`**: Удалить заметку
  - Требует валидный JWT токен
  - Проверяет владение заметкой
  - Возвращает 404, если заметка не существует или не принадлежит пользователю

### Модели Данных

#### Модель Пользователя
```python
- id: int (Первичный Ключ)
- username: str
- password_hash: str (хешированный bcrypt)
- age: int
- role: str (по умолчанию: "user")
```

#### Модель Заметки
```python
- id: int (Первичный Ключ)
- title: str
- content: str
- owner_id: int (Внешний Ключ к users.id)
- created_at: datetime (UTC)
- updated_at: datetime (UTC)
```

## 🛠️ Технологический Стек

### Backend Фреймворк
- **FastAPI**: Современный, быстрый веб-фреймворк для создания API
- **Uvicorn**: ASGI сервер для запуска приложений FastAPI

### База Данных и ORM
- **SQLAlchemy 2.0**: Современный ORM с подсказками типов
- **SQLite**: Легковесная база данных (может быть легко заменена на PostgreSQL/MySQL)

### Аутентификация и Безопасность
- **PyJWT**: Кодирование/декодирование JWT токенов
- **passlib**: Хеширование паролей с bcrypt
- **OAuth2**: Реализация OAuth2 password flow

### Валидация Данных
- **Pydantic 2.x**: Валидация данных и управление настройками с использованием аннотаций типов Python

### Контейнеризация
- **Docker**: Контейнеризация для каждого сервиса
- **Docker Compose**: Оркестрация нескольких сервисов

## 🚀 Начало Работы

### Требования

- Установленные Docker и Docker Compose
- Python 3.8+ (для локальной разработки)

### Запуск с Docker Compose

1. **Клонировать репозиторий**
   ```bash
   git clone <repository-url>
   cd Secure-Notes-API-FastAPI-
   ```

2. **Запустить все сервисы**
   ```bash
   docker-compose up --build
   ```

3. **Доступ к сервисам**
   - Auth Service: http://localhost:8001
   - Notes Service: http://localhost:8002
   - Документация API Auth Service: http://localhost:8001/docs
   - Документация API Notes Service: http://localhost:8002/docs

### Локальный Запуск (Разработка)

1. **Установить зависимости для Auth Service**
   ```bash
   cd auth-service
   pip install -r requirements.txt
   ```

2. **Установить зависимости для Notes Service**
   ```bash
   cd notes-service
   pip install -r requirements.txt
   ```

3. **Запустить Auth Service**
   ```bash
   cd auth-service
   python main.py
   ```

4. **Запустить Notes Service** (в отдельном терминале)
   ```bash
   cd notes-service
   python main.py
   ```

**Примечание**: При локальном запуске обновите `AUTH_SERVICE_URL` в `notes-service/auth_proxy.py` на `http://localhost:8001` вместо `http://auth-service:8000`.

## 📡 Примеры Использования API

### 1. Регистрация Нового Пользователя

```bash
curl -X POST "http://localhost:8001/users/register" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "john_doe",
    "password": "securepassword123",
    "age": 25
  }'
```

### 2. Вход и Получение Токена

```bash
curl -X POST "http://localhost:8001/users/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=john_doe&password=securepassword123"
```

Ответ:
```json
{
  "access_token": "eyJ0eXAiOiJKV1QiLCJhbGc...",
  "token_type": "bearer"
}
```

### 3. Создание Заметки

```bash
curl -X POST "http://localhost:8002/users/notes" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Моя Первая Заметка",
    "content": "Это содержание моей заметки."
  }'
```

### 4. Получить Все Заметки

```bash
curl -X GET "http://localhost:8002/users/notes" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

### 5. Обновить Заметку

```bash
curl -X PUT "http://localhost:8002/users/notes/1" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Обновленный Заголовок Заметки",
    "content": "Обновленное содержание здесь."
  }'
```

### 6. Удалить Заметку

```bash
curl -X DELETE "http://localhost:8002/users/notes/1" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```
